# v2.1.2 — Logseq 2.0.2+ DB-only · 停止旧版适配

给异步任务安排下一次跟进，使用 Logseq 数据库原生属性保存提醒、负责人、项目与操作历史。
本次发布包含从 v1.6.7 到 v2.1.2 的数据库适配和提醒功能更新。

## 兼容性重大变更 / Breaking compatibility change

> [!IMPORTANT]
> **仅支持 Logseq 2.0.2 起的 2.x 数据库图谱（DB graphs）。旧版适配已停止。**
> **Requires Logseq 2.0.2+ within 2.x and a DB graph. Legacy support has been discontinued.**

- 插件版本为 **2.1.2**，最低 Logseq 客户端版本为 **2.0.2**，两者是独立版本号。
- 运行时接受 `>= 2.0.2, < 3.0.0` 的数据库图谱；实际验证环境是 **Logseq Desktop 2.0.2，revision `533ac43`**。其他 2.x 版本尚未逐一验证。
- 不再支持 Logseq 0.x、2.0.0 / 2.0.1、Markdown / Org 文件图谱或旧版插件缓存恢复；也未开放 Logseq 3.x 支持。
- 仍使用旧版 Logseq 或文件图谱的用户，请保留 [v1.6.7](https://github.com/hzphzp/logseq-async-task-timer/releases/tag/v1.6.7)，**不要安装本次更新**。旧版作为历史下载保留，旧适配不再维护。

## 功能更新

- **提醒与任务状态分离**：设置、延后、暂停或取消提醒保留原任务状态；「完成任务」才设置原生 `Done`。
- **历史与撤销**：保存导入、设置、跟进、暂停、恢复、取消、完成与撤销记录。记录未被进一步修改时，可撤销最后一步。
- **新的跟进面板**：按已到期、今天、以后、暂停和历史分组，支持搜索、项目筛选与批量延后。
- **更灵活的时间选择**：分钟预设、自定义时长、明天 09:00、下个工作日 09:00，以及指定日期和时间。
- **可查询的原生属性**：跟进时间、最近检查时间、负责人和项目可在 Logseq 中查看或编辑，提醒与历史随 DB Sync 同步。
- **可靠性更明确的企业微信推送**：通过 2.0.2 的网络代理检查 HTTP 状态与 `errcode = 0`；显示发送结果、最多三次尝试、失败后手动重试，并提供测试按钮。
- **减少打断**：启动或休眠恢复后汇总错过的提醒，不批量补发企业微信；同步刷新保留未保存输入、焦点与展开的历史。

## 修复

- 等待数据库真正可查询后初始化，处理 `db-worker has not been initialized`；暂时断开后自动重连，升级中断后继续剩余记录。
- 将 `[[UUID]]` / `((UUID))` 引用解析为可读标题，用于面板、搜索和通知，保留原笔记中的引用；目标改名后重新读取。
- 切换图谱时取消旧图谱的待执行操作；提醒到期和推送重试前重新检查任务是否已完成、删除或改期。

## 升级步骤

1. **先备份原图谱和插件设置。**
2. 若仍使用文件图谱，先使用 Logseq 官方导入功能迁入数据库图谱，并确认计时数据已导入。插件不会直接导入旧 Markdown / Org，也不会从旧 localStorage 或两个分离属性恢复任务。
3. 下载本页的 **`logseq-async-task-timer-v2.1.2.zip`**，解压后替换插件目录，或通过「Load unpacked plugin」加载。GitHub 自动提供的 “Source code” 包用于源码开发。
4. 重载插件，等待数据库就绪及数据升级完成；核对任务、到期时间、状态和历史。
5. 同一图谱的其他设备也升级至 **v2.1.2**。不要混用旧插件编辑同一组提醒。

数据库中已有的完整 `async-timer` 值会自动升级。原属性、原始计时值、任务正文和原任务状态保留；
已完成任务归入历史，重复启动不会重复升级或复活已取消的提醒。
只有时长、没有到期时间的残留记录会保留，不猜测时间；导入时缺失的数据需从原图谱备份另行恢复。
回退插件文件不会回退数据库，请使用升级前的图谱备份并评估备份之后的新笔记。

## 使用边界与验证

- Logseq 关闭、插件未运行或电脑休眠时，插件不能执行提醒；同步服务器不代替客户端运行提醒。
- 日历预设使用本机时区；工作日仅指周一至周五，不包含节假日表。
- 企业微信设置及推送回执保存在本机。多设备共用 Webhook 时，需要手动指定同一台推送设备。
- Webhook 没有幂等确认接口，超时重试仍可能重复送达；SDK 也不提供跨设备条件写入，同一提醒的同时编辑受 DB Sync 冲突规则约束。
- 已通过 **28 项自动化测试**、真实 **Logseq 2.0.2 worker** 集成测试、**35 条完整记录的迁移演练与迁移后核对**，并完成桌面插件重载后的面板与标题验收。
- 企业微信网络行为使用模拟传输测试，本次验证没有向真实企业微信群发送测试消息。

## English

**This is a breaking upgrade from v1.6.7.** Plugin v2.1.2 requires Logseq **2.0.2+ within 2.x** and a **DB graph**.
Logseq 0.x, 2.0.0, 2.0.1, file graphs and 3.x are unsupported. Legacy users must keep
[v1.6.7](https://github.com/hzphzp/logseq-async-task-timer/releases/tag/v1.6.7); legacy compatibility is no longer maintained.
The tested client is Logseq Desktop 2.0.2, revision `533ac43`; other 2.x releases have not each been verified.

This release separates reminders from native task status, adds pause/resume, retained history and guarded undo,
search and project filters, bulk follow-ups, calendar presets, and native datetime/owner/project properties.
WeCom delivery now checks both HTTP success and `errcode = 0`, shows delivery status and supports bounded retries.
It also fixes startup before the DB worker is ready and unreadable UUID reference titles.

Back up first. File-graph users must migrate with Logseq's official import and verify that complete timer values
exist in the DB graph. Install the built **`logseq-async-task-timer-v2.1.2.zip`**, reload the plugin and upgrade
every device to v2.1.2. Existing complete DB timer values are migrated with source values, original properties,
note text and task status retained. Missing or partial legacy data is not reconstructed. Reinstalling an old
plugin does not roll back the database.

Logseq must be running for reminders to execute. Startup and sleep recovery summarize backlog without pushing
old reminders. Weekday presets exclude weekends, not public holidays. Local Webhook settings and receipts
do not sync; network timeouts can still cause duplicate delivery, and simultaneous edits follow DB Sync conflict rules.

Validation includes 28 automated tests, a real 2.0.2 worker, migration checks for 35 records, and desktop reload/title
acceptance. WeCom transport was mocked; no live test message was sent.
